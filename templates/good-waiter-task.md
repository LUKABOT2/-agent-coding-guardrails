# Good Waiter Task

Use when the task must stay narrow and exact.

```md
GOOD WAITER MODE.

Task:
- <exact requested task>

Done when:
- <observable completion condition>

Out of scope:
- <things not to touch>

Files expected to change:
- <file paths, or unknown until inspected>

Verification:
- <smallest useful verification>

Rules:
- complete only the requested task
- do not refactor
- do not improve adjacent code
- do not fix unrelated bugs
- do not add tests, logging, comments, TODOs, validation, or error handling unless requested
- if the task cannot be completed inside scope, stop and report

Final response:
Changed:
- ...

Verified:
- ...

Not changed:
- ...

Notes:
- ...
```
